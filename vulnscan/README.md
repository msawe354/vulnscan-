# vulnscan — базовый сканер веб-уязвимостей

[![Python](https://img.shields.io/badge/python-3.10%2B-blue?logo=python&logoColor=white)](https://www.python.org/)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)
[![Tests](https://img.shields.io/badge/tests-pytest-informational?logo=pytest)](tests/)

[![Status](https://img.shields.io/badge/status-educational-orange)]()

**vulnscan** — учебная CLI-утилита на Python, которая выполняет базовый аудит
веб-приложения: проверяет HTTP-заголовки безопасности, ищет открытые служебные
файлы по словарю и тестирует HTML-формы на отражённый XSS с помощью безопасного,
неисполняемого пейлоада. Результат выводится в консоль в виде читаемого отчёта и
может быть сохранён в JSON.

Проект создан как портфолио-демонстрация практик AppSec и чистого Python:
модульная архитектура, аннотации типов, изоляция проверок, unit-тесты без сети.

## Возможности

| Модуль | Что делает |
| --- | --- |
| `headers` | Проверяет `Content-Security-Policy`, `Strict-Transport-Security`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, флаги `Set-Cookie` и утечку версий ПО. Для каждой находки — объяснение риска и рекомендация по исправлению. |
| `directories` | Перебирает пути из словаря (`.git/config`, `.env`, `admin`, `backup.zip`, `robots.txt` и др.), определяет статус ресурса и отсекает ложные срабатывания на soft-404. |
| `xss` | Разбирает формы через BeautifulSoup и проверяет отражение инертного пейлоада (`vscan<token>"'><`) без исполняемого JavaScript. Учитывает контекст отражения: текст, атрибут, `<script>`. |
| Reporting | Цветной отчёт в консоли (`rich`), сводка по уровням Critical/High/Medium/Low/Info, опциональный JSON-экспорт. |
| Safety | Таймауты, ретраи, ограничение размера тела ответа, пауза между запросами, пропуск форм с `password`/`file`, запрет ухода на чужой origin. |

**Дополнительно**

- Строгая валидация URL и понятные сообщения об ошибках (недоступный хост, таймаут, TLS).
- Коды возврата, пригодные для CI (`--fail-on high`).
- Полностью типизированный код (`py.typed`), 36 unit-тестов на pytest.
- Работа через `pip install -e .`, `vulnscan ...` или `python -m vulnscan ...`.

## Установка

Требуется **Python 3.10+**.

```bash
git clone https://github.com/your-username/vulnscan.git
cd vulnscan

python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install -r requirements.txt
pip install -e .
```

Проверка установки:

```bash
vulnscan --version
vulnscan --help
```

Для разработки:

```bash
pip install -r requirements-dev.txt
```

## Использование

```bash
# Полное сканирование (заголовки + пути + формы)
vulnscan https://example.com

# Только заголовки и пути, без XSS
vulnscan https://example.com --no-xss

# Сохранить отчёт в JSON и ограничить перебор 30 путями
vulnscan https://example.com --json reports/example.json --max-paths 30

# Свой словарь, больше потоков, пауза 0.2 с между запросами
vulnscan https://example.com -w wordlists/common.txt --threads 20 --delay 0.2

# Локальный стенд с самоподписанным сертификатом
vulnscan https://localhost:8443 -k --timeout 5

# CI: упасть с кодом 2, если найдено что-то уровня high и выше
vulnscan https://staging.example.com --fail-on high --json report.json
```

### Основные опции

| Опция | По умолчанию | Описание |
| --- | --- | --- |
| `TARGET` | — | Целевой URL (схема `https://` подставляется автоматически) |
| `-j, --json PATH` | выкл. | Сохранить отчёт в JSON |
| `-w, --wordlist PATH` | встроенный | Словарь путей |
| `-t, --timeout SEC` | `10` | Таймаут одного запроса |
| `--threads N` | `10` | Потоков для перебора путей (1–50) |
| `--delay SEC` | `0` | Пауза между запросами |
| `--max-paths N` | все | Ограничить число путей |
| `--max-forms N` | `10` | Максимум форм для XSS-проверки |
| `--no-xss` / `--no-directories` | выкл. | Отключить модуль |
| `-k, --insecure` | выкл. | Не проверять TLS-сертификат |
| `--proxy URL` | — | HTTP(S)-прокси (например, Burp) |
| `--fail-on LEVEL` | `high` | Порог для exit code 2 |
| `-v, --verbose` | выкл. | Показывать INFO-детали |

## Что именно проверяется

### Заголовки

| Заголовок | Риск при отсутствии | Уровень |
| --- | --- | --- |
| `Content-Security-Policy` | Нет ограничений на источники скриптов → XSS и сторонние виджеты получают полный контроль над страницей | Medium |
| `Strict-Transport-Security` | SSL-stripping, downgrade на HTTP, кража сессии | Medium |
| `X-Frame-Options` (или CSP `frame-ancestors`) | Clickjacking | Medium |
| `X-Content-Type-Options` | MIME sniffing: загруженный файл может исполниться как HTML/JS | Low |
| `Referrer-Policy` | Утечка URL с токенами во внешние ресурсы | Low |
| `Permissions-Policy` | Неограниченный доступ к камере/микрофону/геолокации | Info |

Дополнительно: `max-age` у HSTS, `'unsafe-inline'` в CSP, некорректные значения
`X-Frame-Options`, флаги `Secure`/`HttpOnly`/`SameSite` у cookie, заголовки
`Server`/`X-Powered-By` (фингерпринтинг) и передача страницы по HTTP.

### Открытые пути

Словарь покрывает типовые артефакты: системы контроля версий, `.env` и конфиги,
бэкапы и дампы, админ-панели, API-документацию, логи и загрузки. Для каждого
ответа учитывается статус:

- `200/204` → ресурс доступен (High для секретов/бэкапов, Medium для остального);
- `401/403` → ресурс существует, но защищён (Low);
- `301/302` на другой хост → возможный open redirect (Low);
- `5xx` → скрытый эндпоинт/ошибка приложения (Info).

Перед перебором сканер запрашивает три заведомо несуществующих пути и сравнивает
их ответы с найденными (статус + коэффициент схожести `difflib`), чтобы не
репортить страницу-заглушку.

### Reflected XSS

Пейлоад выглядит так: `vscan1a2b3c4d"'><` — в нём **нет** `<script>`,
обработчиков событий и `javascript:`. Сканер определяет:

- отражение без экранирования → **High**;
- отражение внутри `<script>` → **Critical**;
- отражение с экранированием (`&quot;`, `&#x27;`) → **Info** (хороший признак).

Формы с полями `password` и `file` не тестируются, а формы, отправляющие данные
на другой origin, пропускаются.

## Коды возврата

| Код | Значение |
| --- | --- |
| `0` | Сканирование завершено, находок уровня `--fail-on` и выше нет |
| `1` | Ошибка запуска: некорректный URL, недоступный словарь, ошибка записи |
| `2` | Найдены проблемы уровня `--fail-on` и выше |
| `130` | Сканирование прервано (Ctrl+C) |

## Тесты

```bash
pytest
```

Тесты не обращаются к сети: `analyze_headers` принимает словарь заголовков,
а проверки директорий и XSS — фейковый клиент с интерфейсом `HttpClient`.

Покрыто:

- нормализация и валидация URL;
- отсутствие/наличие security-заголовков, слабый CSP, короткий HSTS;
- разбор форм, определение контекста отражения, экранированный вывод;
- парсинг словаря, soft-404, маппинг критичности.

## Ограничения

- Сканер **не** обходит аутентификацию, не работает с SPA/JS-роутингом и не
  выполняет JavaScript, поэтому не видит DOM-based XSS.
- Перебор путей — по фиксированному словарю, без рекурсии и fuzzing.
- Нет проверки CSRF, SQLi, SSRF, IDOR, конфигураций TLS и версий библиотек.
- Soft-404 эвристика может ошибаться на страницах с динамическим контентом.
- Находки XSS требуют ручной верификации (сканер фиксирует отражение, а не
  выполнение кода).

Для более глубокого тестирования используйте специализированные инструменты
(OWASP ZAP, Burp Suite, nuclei, ffuf).
